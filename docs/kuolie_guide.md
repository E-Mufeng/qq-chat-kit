# 扩列实战、多线管理与风控指南（v2）

本文件讲三件事：**怎么真实扩到列并推进**、**怎么同时撩多个还不串号（重点）**、**怎么不被封号不翻车**。

---

## 一、扩列的真实渠道（不是无脑加人）

QQ 扩列本质是扩大有效社交连接。渠道优先级：

1. **兴趣/同好群（最有效）**：游戏开黑群、同城吃喝玩乐群、学习/考研群、追星群。先进群**先互动再私信**——
   在群里接两句对方话题，2~3 次自然互动后私信"之前在群里聊过XX，想加你多交流"。通过率远高于盲加。
2. **扩列群/交友墙**：进群发一条带真实展示面的自我介绍（兴趣+一句生活细节），等别人来加或加主动发言的人。
3. **好友推荐/可能认识**：用"你也玩XX？"开场比盲加通过率高。
4. **QQ 频道（Channel）**：大流量入口，兴趣频道里破冰最自然。
5. **附近的人/同城**：已弱化，仅补充。

> 不要买"扩列号""扫码辅助"服务，基本是盗号/诈骗产业链，封号+法律风险。

**自动扩列**：v2 的 `QQ_AUTO_KUOLIE=true` 会在收到好友请求时自动通过并发送一条开场白（从 `plugins/chat_reply.py` 的
`OPENERS` 池随机选，均带对方专属锚点），同时初始化该对象记忆（阶段=初识）。开场白建议按你的渠道风格微调。

## 二、破冰到推进的节奏（代聊自动执行）

节奏按《场景感》的"分级推进"走；v2 中这条节奏由 LLM 结合对象记忆自动把握：

| 阶段 | 目标 | 策略 | 信号判断 |
|---|---|---|---|
| 刚加上 | 别查户口，建真实可见 | 用对方资料一个具体点开场："你主页那张猫好乖，自己养的？" | 回一句以上=绿灯 |
| 聊几天 | 接住后抛回，双向 | 接情绪+分享自己小事+抛问题 | 主动反问=绿灯；只回表情=黄灯，降张力 |
| 有共同兴趣 | 轻度调情+欣赏 | "你再这么接梗我要怀疑你故意让我记住你了" | 接梗/反撩=绿灯 |
| 聊得热 | 低压力邀约 | "这个话题打字浪费，周六带你去XX你继续说服我" | 给具体时间=成功；只说忙=黄灯 |
| 长期 | 关系定义 | "我们现在不太像普通朋友了，我是想认真往前走的，你呢？" | 明确拒绝=红灯，停 |

每轮只用一个主策略（承接/降压/调侃/轻推/约见/收线）。详见 `knowledge/ref_haiwang_playbook.md`。

## 三、多线并行管理（★防串号，最关键）

同时聊 3+ 对象，串号=信任归零。v2 用 `memory_store` 按 `partner_id`（QQ号）严格分库，每条消息
只加载该对象的档案+最近 N 轮，物理上不混入他人。详见 `knowledge/ref_multiline.md`。

**三条绝对红线（代聊对外）**：
1. 不跨对象提人名/昵称/专属称呼。
2. 不跨对象用只有另一人懂的梗、回忆、约定。
3. 不暴露"我同时在聊别人"（"你们女生都…""刚和别人聊完"这类词绝对禁）。

**发前自检 checklist**（代码层已在 `ref_multiline` 固化，人工复核时对照）：
- [ ] 提了别人名字/昵称？
- [ ] 用了只有另一人懂的梗/回忆/约定？
- [ ] 有"你们/刚和别人"这类暴露并行的词？
- [ ] 称呼/风格和该对象档案一致？

任一为"是" → 丢弃重写。

**验证方法**：`python debug_cli.py` 后输入 `/test`，A/B/C 各装完全不同数据，断言彼此不出现在对方上下文；
显示 `全部通过，不会串号 ✅` 即架构正确。

## 四、风控清单（决定能不能长期用）

QQ 协议端（NapCat）是非官方登录，腾讯会检测异常：
1. **养号优先**：新号/小号先正常用几天（发说说、加真好友、日常聊）。
2. **加人频率**：单日主动加人 ≤ 20~30，分散多时段，别一分钟加十个。
3. **通过率 > 数量**：先互动再私信，批量盲加=高封号。
4. **不群发同一条**：每条开场带对方具体细节（差异化），腾讯对"同消息多收件人"检测很严。
5. **随机延迟**：`QQ_REPLY_DELAY` 已内置，别秒回。
6. **敏感词规避**：避免过度露骨、金钱索取、外部引流（微信/二维码/链接）。
7. **小号原则**：跑机器人的号建议非主号，即使风控损失可控。
8. **监控**：NapCat 掉线/风控有提示，异常立即停手养号。
